Key constraint from RESEARCH.md:
"$derived cannot have side effects (posting to Worker). The Worker trigger must be in a $effect that watches sortState and filteredRows."

Pattern for Worker-aware sort pipeline:
1. Keep existing $derived sortedRows for small datasets / no-sort cases
2. Add $state workerSortedRows = [] as parallel result holder
3. Add $state sortLoading = false
4. Add $effect watching sortState + filteredRows: if length > 10k AND sort active, post to Worker and return
5. Modify sortedRows $derived: if workerSortedRows.length > 0 AND sort active, use workerSortedRows instead

CRITICAL: $derived cannot directly call sortWorker.postMessage(). The approach:
- sortedRows $derived does the main-thread sort synchronously for < 10k rows
- A separate $effect watches sortState + filteredRows, fires the Worker for > 10k rows
- When Worker responds, workerSortedRows is set (as already-processed ProcessedRow[])
- The final visible rows = workerSortedRows (if set and sort active) || sortedRows ($derived)

IMPORTANT for re-processing: The Worker receives raw _original data and sorts it. The response contains sorted raw objects. These need to be re-wrapped into ProcessedRow[] format. Use engine.processRows() — but engine is created inside the two-phase $effect, not accessible in the Worker callback.

Better approach:
- Instead of re-wrapping, derive the ProcessedRow[] by re-ordering the already-processed processedRows in the Worker callback order.
- The Worker returns sorted _original data. Map the sorted originals back to their corresponding ProcessedRow via an index map built from processedRows.

Pattern for mapping without re-processing:
```typescript
// Build an index map from raw data to processedRow
const originalToProcessed = new Map(processedRows.map(pr => [pr._original, pr]));

sortWorker.addEventListener('message', (e: MessageEvent<{ sorted: Record<string, unknown>[] }>) => {
  const sortedOriginals = e.data.sorted;
  workerSortedRows = sortedOriginals.map(orig => originalToProcessed.get(orig)!).filter(Boolean);
  sortLoading = false;
});
```

This requires the map to be rebuilt whenever processedRows changes. Do it inside the Worker creation $effect OR as a $derived.

    4. Add $effect for Worker lifecycle (create once, handle messages, clean up):
    ```typescript
    $effect(() => {
      // SSR guard — Worker is not available in Node/SvelteKit SSR
      if (typeof Worker === 'undefined') return;

      let worker: Worker;
      try {
        worker = new Worker(
          new URL('./sort.worker.ts', import.meta.url),
          { type: 'module' },
        );
      } catch {
        // Worker blocked (CSP or env) — silent fallback to main-thread sort
        return;
      }

      worker.addEventListener('message', (e: MessageEvent<{ sorted: Record<string, unknown>[] }>) => {
        const sortedOriginals = e.data.sorted;
        // Map sorted originals back to their ProcessedRow without re-processing
        const origToProcessed = new Map(processedRows.map((pr) => [pr._original, pr]));
        workerSortedRows = sortedOriginals
          .map((orig) => origToProcessed.get(orig))
          .filter((pr): pr is ProcessedRow => pr !== undefined);
        sortLoading = false;
      });

      worker.addEventListener('error', () => {
        // Worker error — fall back to main-thread sort
        sortLoading = false;
        workerSortedRows = [];
      });

      sortWorker = worker;

      return () => {
        worker.terminate();
        sortWorker = null;
      };
    });
    ```

    $effect(() => {
      // Watch sortState and filteredRows
      const key = sortState.key;
